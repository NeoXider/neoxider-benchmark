Filters

These apply to the charts and the table alike. Size is by published parameter count — small up to 20B, medium 20–150B, frontier above that; the thresholds sit where the way you run a model changes, not at round numbers. Vendors do not publish sizes for closed models, so those are placed by the vendor's own positioning and marked as such on hover.

Tokens → score

X axis — net tokens, on a log scale because token spend differs by multiples rather than by percentages. Y axis — percentage of the measurable levels cleared, ranged to the data rather than from zero: models cluster near the top, and a fixed 0–100 spends half the chart on empty space. The axis is a percentage rather than a raw score on purpose: runs use different profiles — 24 levels against 82 — and plotting the absolute put a model at 93.8% three times higher than one at 85.4%, comparing the length of the distance while reading as a difference in strength.

Cost → score

X axis — run cost, Y axis — percentage of the measurable levels cleared. A free tier is a billing arrangement, not a free model — the same model is metered elsewhere — so cost is computed from the measured tokens at the model's published rate and marked with a ~. Where the CLI reports a real charge it is used as-is. A rate of zero is never treated as a price: it would pin the run to the axis and make any quality look infinitely efficient. Unpriced runs are listed below the chart.

Run it yourself

Every number on this page is reproducible: tasks are generated from the seed, so a given model gets exactly the task set shown here. Add your own model and it lands in the same table.

git clone https://github.com/NeoXider/neoxider-benchmark
cd neoxider-benchmark

python run.py --list                        # tasks, levels, categories
python run.py --model opencode/hy3-free --profile minimal
python run.py --model claude/claude-opus-5 --profile full
python run.py --model codex/gpt-5.6-terra --tasks calc,spatial --levels 1-5

python run.py --model <id> --status         # what is still missing
python run.py --report                      # rebuild this page

A run is cumulative. Start with --profile minimal, top it up to --profile full later, and only the missing levels are computed. Change a task and raise its VERSION, and just that task's stored levels are recomputed — the rest stand.
